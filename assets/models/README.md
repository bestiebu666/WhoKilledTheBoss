# 模型放这里 —— 文件名 = 模型名（不是位置名）

```
assets/models/SM_F_Desk3P.glb       ← 两排三人办公桌都用它（一排 = 3 个工位连在一起）
assets/models/SM_F_Plant.glb        ← 4 盆绿植都用它
assets/models/SM_A_Npc_Feng.glb     ← 凤凰男
assets/models/SM_J_Bag_FengDesk.glb ← 凤凰男桌上那只包
```

放进来、重开游戏，就自动替换掉灰盒方块。**不用改代码、不用在编辑器里连线。**
没有文件的模型继续用灰盒方块，不会报错，所以你一天做三个、一天做五个都行。

> ⚠️ **新加的文件必须先让 Godot 导入一次**，否则游戏里根本加载不到（`ResourceLoader.exists` 返回 false）：
> ```bash
> "D:/Godot_v4.7.2-stable_win64.exe/Godot_v4.7.2-stable_win64_console.exe" \
>   --headless --path "." --import
> ```

## 一个模型可以顶多个位置

这是这个工程最省事的地方 —— **46 个摆放位置，只需要做 33 个模型**。

| 模型 | 顶几个位置 |
|---|---|
| `SM_F_Desk3P` | **2 组办公桌**（每组 = 3 个工位连成一排，含隔板/抽屉/显示器/桌上绿植；**没有椅子**） |
| `SM_F_Plant` | 4 盆绿植 |
| `SM_B_Window_EW` | 2 扇东墙窗（北墙那排小窗已换成落地窗，见下） |
| `SM_B_Window_Wall` | **2 扇北墙落地窗**（并排铺满整面北墙；同一个 glb 实例两次 —— 作者说的「素材复用拼接」） |
| `SM_B_LampPanel` | 6 盏吊灯罩 |

表里写了「**×N 处复用**」的行，就是让你**只做一个、只导出一份**，别加 `_01` / `_02` 后缀。

**「一整组」也可以是一个模型。** `SM_F_Desk3P` 就是例子：一排 3 个连着的工位
（桌、隔板、抽屉柜、显示器、桌上绿植）做成一整个 glb，场景里只放 2 次。
比做 6 张单桌 + 6 把单椅省事得多 —— 而且不会出现「桌椅对不齐」的问题。

**而且同一份模型可以在场景里转着放。** 这两组办公桌就是**背靠背拼成一个岛**的：
一组不转（人朝北）、一组在 `room.json` 里写了 `"rot": 180`（人朝南），
两组的隔板对隔板贴在一起、中间没缝。
⚠ 新桌子 `SM_F_Desk3P` 没有椅子（老那份 `SM_F_DeskBench` 把椅子做进去了），进深从 1.52 米
掉到 0.665 米，所以第二组的 z 也跟着挪到了 -3.935 —— **换资产时记得看进深有没有变**。
**你只需要做一份、照「坐在 -Z 那一侧」做**，翻过来是场景干的 ——
别自己在 Blender 里把模型做反，那样另一组就正不过来了。
对照表里凡是转了向的位置都会写「绕 Y 轴转 X°」，照 0° 做即可。

## 从别人手里收到 glb 时

AI 生成（Tripo 之类）或别人做的 glb 通常**不能直接用**：一百多万面、4096 贴图带法线和 ORM、
原点在奇怪的地方、正面朝 `+Z`。**成批收就用 `tools/model_prep.py`**（见工程根目录 README 的
「一次交来一堆？」一节），它会：合并对象 → 烘变换 → 按轴等比缩放 → 原点挪到底面中心 →
材质瘦身（只留 Base Color，Metallic 0 / Roughness 0.85）→ 贴图封顶 2048 →
（可选）`yaw` 转正朝向 →（可选）`tint` 换色 → 出四视图 → 导出。

> ⛔ **默认不砍面，也别自己砍。** 作者明确要求过「不要砍我的建模面数，点进游戏里发现建模都崩了」。
> 1.5M 面的沙发就是 1.5M 面、48 MB 就 48 MB。真要瘦身是回 Blender 手工重拓扑的事。

先单独看清一个文件时，用这两个（都不需要起 Blender 之外的依赖）：

```bash
python tools/glb_peek.py "D:/桌面/办公桌.glb"     # 最快：只读 GLB 头 + JSON，打面数/贴图/包围盒
"D:/blender/blender.exe" --background --python tools/model_probe.py -- "D:/桌面/办公桌.glb" "docs/probe"
```

## 完整清单

看 `docs/建模对照表.html`（浏览器打开），或者 `docs/建模对照表.csv`（丢进表格软件）。
表里有「摆在哪里（场景节点）」和「导出文件名（= 模型名）」两列 —— **导出时照第二列命名**。

## 导出设置

| 项 | 值 |
|---|---|
| 原点 | 物体**底面中心**（底面要贴在对照表给的 y 上）—— 没有例外 |
| 朝向 | 面向 -Z（glTF 默认正面）。位置转了向由场景负责，你照 0° 做 || 单位 | 米，Y-up |
| Apply Transform | rotation、scale、**location 都要 Apply** |
| 材质 | Metallic 0，Roughness 0.85，只用 Base Color |
| 不做 | 法线贴图、ORM 贴图、真实反射、Metallic |

**location 也要 Apply 是最容易忘的一条**：忘了的话模型原点会留在别处，导进游戏后整体下沉或跑偏半个身位。

## 两个踩过的坑

**① 对象名别用位置名。** Blender 里的对象名会变成 glb 里的节点名。如果你把对象也叫
`SM_F_Desk_01`，场景里就会出现两个同名节点（一个是你挂模型的宿主、一个是模型内部的网格），
排查起来很痛苦。**对象名用模型名就行**（`SM_F_Desk`），或者干脆叫 `Mesh`。

**② 尺寸照灰盒做。** 灰盒的尺寸就是目标尺寸，游戏允许在 0.6～1.6 倍之间浮动，
不必卡到小数点后两位 —— 高矮胖瘦有变化是好事。但差出这个范围会点名提醒你
（顺便排查一下是不是忘了 Apply Scale）。

⚠️ **对照表里的尺寸已经含了统一缩放**（`room.json` 的 `prop_scale`，现在是 0.8）。
原来 0.75 米高的工位桌，表里会写 0.6 —— **照表做就行，不要再自己缩一遍**。
**例外**：2026-10-05 之后交付的那几批（沙发、饮水机、发财树、人台展架、雕塑、四个角色）
是照「游戏里的最终尺寸」归一化过的，`room.json` 里给它们写的是 `scale: 1.0`，
所以它们的 `size` 就是模型实测尺寸，**不再乘 0.8**。

**④ 朝向：AI 生成的模型正面几乎都朝 `+Z`，和工程约定相反。**
别手工在 Blender 里转 —— 在 `tools/model_prep_list.json` 里写 `"yaw": 180` 让脚本转，
这样四视图能验、也能重跑。判据是**四视图的第 1 格**：
第 1 格（相机在 `-Y`）看到的是模型的 `+Z` 侧，**这一格是正脸就说明它朝 `+Z`，要转 180°**。

**③ 主角不做模型。** 主角是一件「神器」，第一人称下看不到自己，也没有对应的槽位 ——
对照表里找不到「玩家」这一行，这是故意的。

## 导完怎么核对

开游戏看控制台，会播报：

```
[模型槽位] 46 个位置，一共只需要做 33 个模型
[模型槽位] 已换 19/33 个模型，还有 22 个位置在用灰盒
[模型槽位] 已替换：SM_F_DeskBench, SM_F_Plant, SM_F_Sofa, ...
```

尺寸对不上或面数超预算，它会点名：

```
[模型槽位] SM_F_Desk（工位桌）面数 1800 超预算 700 —— 如果这是作者刻意保留的高模，
          就把 data/model_map.json 里这条的 tri 改成实际面数；否则再考虑减面。
```
